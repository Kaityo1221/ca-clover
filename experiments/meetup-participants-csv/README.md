## 現時点の実装

- **csv-core.mjs**: Meetup 1件の参加状況とアカウント名から、Excel向けUTF-8 BOM付きCSVをメモリ上で生成する純粋関数。ファイル保管は行わない
- **member-pages.mjs**: API呼び出し関数を外から受け取る、上限付きの参加者ページ分割補助。実際のAPIアクセスは未実装
- **preview.html / preview.mjs**: 仮名 Trainer_A などだけを使うコンパクトMeetupカードのローカルプレビュー。「↓ CSV」で架空データのCSVのみダウンロード可能。実データへの接続なし
- **export-failure.mjs**: APIエラーのHTTPステータスまたは制御用コードを安全な日本語表示へ分類。レスポンス本文・参加者名・トークンをエラー表示へ転記しない
- **テストファイル**: 出力形式、辞退者除外、CSV数式注入対策、重複、欠落、ページ分割、カーソルループ、人数不整合、現地日付、失敗時の表示

## 暫定CSV契約

| 列 | 値 |
|---|---|
| アカウント名 | Campfire username（実API通信後に確定） |
| 参加表明 | ACCEPTED, CHECKED_IN の両方を「あり」 |
| チェックイン | CHECKED_IN を「済」、ACCEPTED を「未」 |

DECLINED はCSVから除外。未知の状態、矛盾した重複、参加者名の欠落、ページ未取得、ステータス全件取得の確認がない場合は**部分CSVを出さずに失敗**する。これらの集計定義はCampfire本家表示と照合するまでは暫定。

出力名: meetup_YYYYMMDD_EVENTID.csv（ISO8601のオフセット付き開催日時から現地日付を使う）。ヘッダー + 参加者行、UTF-8 BOM、CRLF、引用符で囲む。セル先頭のExcel数式候補はアポストロフィで無害化する。

## 本番統合までに必要なゲート

1. 復元・CAマスター保護の全工程完了。復元側の作業ファイルやブランチを触らない
2. 所属コミュニティのMeetup URLによる**読み取り通信診断**で、終了済みとLIVE中の rsvpStatuses、members.username が取得できるか確認
3. API利用条件と権限を確認。本番では本人確認済みのCA/許可管理者のみ。**サーバー側**で event ID と担当communityの一致を検証する
4. CSV出力をサーバー側のオンデマンド取得に接続。機密トークンをクライアントへ渡さず、名簿・レスポンス本文をDB/Storage/ログ/解析ツールへ保存しない
5. 同時実行・レート制御（全体の共有制御）、1ユーザー多重実行抑止、適切なタイムアウトと429バックオフ。通常の15分巡回Cronとリソースを分離
6. 画面への組み込みは My Community Meetupカード右下の「CSV」。カードの詳細タップは残し、ダウンロードボタンとのイベント干渉を防止
7. 権限と不完全取得の負荷・回帰テストにPASSしてから、別途、本番リリース判断

**注意**: このブランチの現状は権限確認も実Campfire API取得も含まない。現状のプレビューは一般ユーザーに配布して実データを扱う用途には使用しない。

## 独立オーケストレーターと300件負荷試験（2026-10-16追加）

新規の export-coordinator.mjs / export-coordinator.test.mjs により、認証済みユーザーとイベントを引数に、**外部から注入される**サーバー側権限検証 → 同時実行枠獲得 → イベント・RSVP一覧 → 参加者全件ページ取得 → CSV化 → 実行枠解放、の処理順序を検証する。

実装内には外部HTTP呼び出し、実際の認証、Supabaseへの接続、DB操作、タイマーや個人名簿キャッシュを含まない。

- **7件の追加テストがNode.js 22でPASS**。以前の27件と合わせて、テスト項目は計34件
- 300件の**模擬**同時要求を処理したところ、試験用のローカル枠3件が成功、297件がBUSY、イベントデータの読込開始は3件、最大同時枠は3件、終了時未解放枠は0件
- 権限がない場合は参加者データの取得処理を呼ばずにFORBIDDEN
- 取得失敗、RSVPステータス未完了、混雑時は不完全なCSVを返さない
- 外部APIエラー本文・アカウント名をユーザー表示に混ぜない
- **重要：テスト用の枠は単一プロセス内のみ**。本番の共有同時実行制限ではない
- 本番統合時は全Edge Functionインスタンスにまたがる**原子的・期限付き共有リース**が別途必要。単純なJavaScriptのMapやローカルSemaphoreでは負荷制御として不十分
- RSVPステータスが本当に全件取得できるかはAPI実通信検証まで未確定。このエビデンスがない場合はfail closed
- 既存のMy Community画面や本番Supabaseを変更した事実はない

ブラウザのヘッドレスChromium起動によるスクリーンショット検証は現在の実行環境でタイムアウト。JSロジックと既存の模擬DOM試験は別途PASSだが、実ブラウザ/iPhoneによる最終確認は未実施のまま。


## APIデータ構造のオフライン診断（2026-10-16追加）

新規 **api-diagnostic-contract.mjs** と **api-diagnostic-contract.test.mjs** を追加。
取得済みデータを**メモリ上でのみ**検査する純粋関数であり、APIへのHTTPリクエストは行わない。

- 判定結果は **PASS / PARTIAL / STOP**
- チェック項目: イベントID一致、参加者ページ完了、member totalCount、checkedInMembersCountと状態明細の一致、参加表明者のアカウント名とIDの対応、未知の状態、重複の検出
- 表示結果は人数、判定コードだけ。ID、username、トークン、GraphQLレスポンス本文は出力しない
- **最重要**: 現行Campfire APIクエリの rsvpStatuses は、配列として返る見込みであっても、全件完了を示す totalCount / pageInfo が見つかっていない。**人数が合っただけでは全件取得の証明にはならない**
- **PARTIAL** は、取得値に明白な矛盾はないが、rsvpStatuses が全件かの独立した証拠がない状態。**CSV本番出力不可**
- **STOP** は欠落、数値不一致、未知の状態、ページ未完了など。**CSV本番出力不可**
- **PASS** は各検査が一致し、rsvpStatuses の全件性を別途確実に確認したことを明示した場合に限る。**テスト用の statusCompletenessVerified=true を、本番で無条件に設定しない**
- バックエンドへの統合前に、実通信でGraphQLフィールドの存在、返却件数の意味、全件性、利用権限を確認する必要がある

オフライン模擬テスト: 新しい**11項目PASS**。既存のCSV・ページ分割・表示の27項目と合わせて**38項目PASS**をこの更新で確認した。以前に実施した7項目のローカルNode.js負荷・連携テストを含めたテスト定義は計45項目だが、今回の検査時に再実行したのは38項目のみ。

### 実通信の解禁条件

1. 復元作業の保護・比較結果が承認されていること
2. 利用するCampfireの本人権限とAPI利用条件が確認されていること
3. 原則、CA自身が管理する終了済みMeetupとLIVE Meetupをそれぞれ1件選定すること
4. 小さいページ上限で読み取り専用のAPI通信を開始し、エラー/429時は停止すること
5. 出力は個人のユーザー名・ID・トークンなしの**件数と判定コードのみ**とすること。生の回答をログへ保存しない
6. PARTIAL/STOPならCSV実装のAPI連携へ進まず、取得できない理由を解析すること
