# CAお楽しみ抽選会 工程① Next.js 403 修正後の隔離再試験

作成日: 2026-11-17 JST。工程判定: **PARTIAL**。本番: **NO-GO**。

## 変更
- `app/api/[...path]/route.js` のオリジン判定を修正。
- Next.js `request.url` がリバースプロキシ内部のURLとして組み立てられても、ブラウザーからの正当なPOSTを受付可能にする候補修正。
- 許可するブラウザーの `Origin` を `http://127.0.0.1:41739` または明示設定した `LOTTERY_QA_HTTPS_ORIGIN` の完全一致に限定。
- `Host` を隔離Nextの `127.0.0.1:41739` または明示設定した隔離HTTPS名に限定。
- 隔離HTTPS名は `.test` / `.local` で終わるホスト名のみ認め、本番環境とVercelは引き続き拒否。
- API転送先は `http://127.0.0.1:41738` のみ。バックエンド本体には変更なし。

## 次の実機・実環境試験
1. 隔離QA DB・GoTrue・PostgREST・受付APIの接続先が従来どおりローカルQAであることを確認する。秘密値はログ・証跡に保存しない。
2. Next側で `npm ci`、`npm run dev`。ローカル試験では `http://127.0.0.1:41739` を開き、`POST /api/rooms` が未ログイン時 **401**、ログイン後 **200** になることを確認する。403が残る場合は通信のOrigin/HostとLOTTERY_QA_HTTPS_ORIGIN設定の不一致を、秘密値を含めず採取する。
3. バックエンド側の従来QA `frontend/qa.cjs` を、隔離接続先が正しいことを確認して実行する。変更の影響範囲としてNext経路のルーム作成・参加・参加証復帰・CA名簿更新を検証し、変更のない負荷試験は原則再実施しない。
4. 物理スマホのHTTPS試験には独立した `https://<隔離名>.test` または `.local`、スマホが名前解決できるローカルDNS、信頼済み証明書、ローカルNextへのHTTPSリバースプロキシを用意。Nextと受付APIの両プロセスで `LOTTERY_QA_HTTPS_ORIGIN` を同じ値にする。インターネットへ公開しない。
5. スマホのカメラでQRを読み取って登録、同端末で再度開いて参加証復帰、別端末で復帰コード交換、CA側の人数・名簿更新、SafariのURLコピー→ペーストまで検証する。
6. 共有プロキシでは全参加者が同じ送信元IPとして見える可能性がある。レート制限320 join/分などが会場利用に与える影響を評価する。
