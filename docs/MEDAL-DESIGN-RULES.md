# CA Clover 🍀 メダルデザイン共通ルール

更新：2026-10-17 / E案を本番採用（PR #164、GitHub Pagesデプロイ成功） / 適用対象：CA Medal Rally の通常表示・ADMIN見本帳、全Community共通

## 目的

アイコンの色が3D照明で白く飛ぶ、または二つの白い反射が強く載る問題を防ぐ。E案として、元画像の色を保ちながら傾けたときに動く柔らかい反射を加える。
一覧（2D）と3Dのアイコン面が可能な限り同じ色・配置になることを優先する。
**KOGAの黄色も、がちもんくらぶの青も、個別の色補正ではなく共通処理で再現する。**

## 単一の設定ソース

- **実装の正本**：`docs/medal-render-preset.js` に公開する `MEDAL_DESIGN_RULES`
- **適用先**：`docs/stamp-rally.html` が3D生成時に明示的に読み込む。
- プリセットは `WebGLRenderer.prototype` を書き換えない。設定は明示的に適用する。
- 本文は仕様であり、数値を変更するときはプリセットと回帰テストを同時に更新する。

## 部位ごとのルール

| 部位 | 設計 |
| --- | --- |
| Communityアイコン面 | 元画像は `MeshBasicMaterial` / `toneMapped: false` / 白ベースで色を正確に保持。ライトによる反射は元画像にはかけない。 |
| アイコン画像 | `sRGBColorSpace`。2Dと同じ `saturate(1.12) contrast(1.06)` を画像素材に1回だけ適用。 |
| サイズ・位置 | 標準 `0.97` 倍・中央配置。既存のがちもんくらぶ専用倍率・オフセットは保持。 |
| 艶レイヤー（E案） | 元画像とは別に `FrontFaceGloss` の薄い `MeshPhysicalMaterial` を載せる。opacity `0.18`、metalness `0`、roughness `0.42`、reflectivity `0.24`、clearcoat `0.30`、clearcoatRoughness `0.32`。透明・深度書き込みなし、前方オフセット `0.0006`。 |
| 傾斜連動の反射 | `FrontFaceReflection` に独立した半透明 `ShaderMaterial` を使用。視線と面法線で反射方向を計算し、固定された柔らかい帯状光源との交点から光沢を描く。最大opacity `0.15`。時間ベースの強制移動なし。厚み・側面・裏側には描かない。読み込めない画像は従来通り2Dフォールバック。 |
| 金枠 | `MeshPhysicalMaterial` の金属光沢を維持。色 `0xb8922e`、metalness `0.95`、roughness `0.34`。 |
| 裏面・ピン | 既存のPBR金属仕上げ、刻印、焼き印演出を維持。 |
| トーンマッピング | 金属・艶レイヤーにACES Filmicを維持。露出 `0.92`。**アイコン画像自体には適用しない**。 |
| 3D操作 | 回転、ドラッグ、鈴木専用演出、デザイン履歴、取得・再会の表示を変えない。 |

## 2026-10-17 採用仕様：E案（自然な反射帯）

E案はD案の照明・金枠・色補正・画像位置・裏面を維持し、艶レイヤーのroughnessを下げてclearcoatを増加する。さらに反射帯用の薄い別メッシュを追加。GLBのFrontFace geometryを複製し、法線が表側の面にのみ反射を描く。実際のモデル回転・ドラッグに追従するため、時刻・アニメーションで光をスライドさせる加工はしない。双方の複製geometryとmaterialを表示終了時に解放する。KOGAの黄色などアイコンの元画像は無照明のまま。

**反映記録**：2026-10-17、PR #164（`57979503`）を `pages` に反映、GitHub Pagesデプロイ成功。iPhone実機で「がちもんくらぶ」の表示について利用者から好評を確認。これをE案の採用判断として記録する。ただしKOGA・KOTO KIBAを含む全Community・全角度の定量的な色差/反射比較が完了したことまでは意味しない。**次回以降の変更でも**黄色・青・淡色・暗色と回転時の実機確認は必須。

## エフェクト変更の法則（E案を基準にした共通運用）

### 1. 「素材」「艶」「反射」「金属」を混ぜない

- **元画像の色**：Communityのアイコンは `FrontFace` の `MeshBasicMaterial`（`toneMapped: false`）に載せ、sRGBと既定の2D/3D色フィルタを維持する。元画像自体に光源やPBR反射を適用しない。色再現の不具合を光沢パラメータでごまかさず、画像の取得、sRGB、フィルタ回数、表示経路を先に調べる。
- **表面全体の艶**：`FrontFaceGloss` はベース画像の上の独立した薄い `MeshPhysicalMaterial`。面全体の艶感を担当する。アイコン画像を再描画・再保存しない。
- **表を傾けると動く反射**：`FrontFaceReflection` は別の `ShaderMaterial`。固定した仮想ソフトボックスに対し、実際の面法線とカメラ方向から反射位置を毎フレーム計算する。時間で白帯を移動させたり、白い点光源を2個重ねたりしない。
- **金枠と裏面**：`MedalBody` の金属、`back_shell`、裏面の刻印、`pin_assembly` は独立した既存仕様。**「表の反射」の要望で裏面・ピン・金枠・共通照明は変更しない。**

### 2. パラメータを触ると何が起きるか

| 調整したいこと | 主に変更する対象 | 効果と注意点 |
| --- | --- | --- |
| 面全体の艶の存在感 | `faceGloss.opacity` | 大きいほど艶レイヤーが強く重なる。白っぽさ・彩度低下が起き得るため色再現を再確認する。 |
| ハイライトの鋭さ | `faceGloss.roughness`、`faceGloss.clearcoatRoughness` | 小さくするほど鋭い/くっきりした反射になりやすい。大きくするとぼけて広がる。見た目の反射量との一対一の換算はできない。 |
| 艶の物理的な出方 | `faceGloss.reflectivity`、`faceGloss.clearcoat` | 反射・クリアコートの寄与を調整する。`opacity` や環境マップにも左右されるため、必ず実機で比較する。 |
| 動く反射の明るさ | `faceReflection.maxOpacity` | 仮想反射帯の**そのレイヤー単体**の不透明度上限。E案は `0.15`。`faceGloss.opacity=0.18` とは別物で、合計の白さを15%以下と保証する値ではない。 |
| 反射帯の横幅と長さ | `halfWidth`、`halfLength` | 横幅を広げれば帯が太く、長さを増せば帯が長く映りやすい。形状と角度で見え方は変わる。 |
| 帯の柔らかい縁 | `edgeFeather` とシェーダー内の `smoothstep` | 値・補間を調整して境界をなめらかにする。白い線や点として強く出さない。 |
| 反射が当たる位置・角度 | `lightX`、`lightY`、`lightZ` | 仮想ソフトボックスの**固定位置**を調整。面法線との関係で見える場所が変わる。時計やスクロール位置に結び付けない。 |
| レイヤーの重なり・ちらつき | 各 `zOffset`、`polygonOffset` | 色・光量ではなく描画面の干渉を抑えるための値。見た目を強める目的で安易に増やさない。 |
| メダル全体の照明 | `lights.*`、`exposure` | 表だけでなく金枠・裏面・金属に影響する。表面反射だけの調整では触れない。 |

### 3. B→C→D→Eで学んだこと

- **B案**：薄い艶レイヤーの `opacity=0.09`。色を壊さず艶を戻す段階。
- **C案**：`opacity=0.12` に増やす。表面に載る光沢の存在感を少し強めた。
- **D案**：`opacity=0.16`、`roughness=0.55`、`reflectivity=0.16`、`clearcoat=0.20`、`clearcoatRoughness=0.50`。全体の艶は増したが、これだけでは傾斜に応じて動く明瞭な反射帯の代わりにはならない。
- **E案（現行基準）**：`faceGloss` は `opacity=0.18`、`roughness=0.42`、`reflectivity=0.24`、`clearcoat=0.30`、`clearcoatRoughness=0.32`。さらに `FrontFaceReflection`（`maxOpacity=0.15`、柔らかい帯状光源）を独立して追加。**「艶を増す」作業と「動く反射を作る」作業を分離することが決め手**。
- これらは実装した値の変遷であって、数値を増やすほど常に良くなるという法則ではない。色飛び・白い二点反射が再発したら強化ではなく再調整する。

### 4. 表だけを変えるための実装ガード

1. `front instanceof THREE.Mesh` を確認し、`front.geometry.clone()` で艶・反射それぞれのメッシュを作り、`front.add(...)` で表面に追従させる。元のGLB geometryは変更・disposeしない。
2. `THREE.FrontSide` と `vLocalNormalZ < 0.92` の破棄判定で、**表側のアイコン面だけ**に反射を許可する。GLBの裏面・縁・側面に反射帯を回さない。GLB変更時は法線と形状の再検査が必要。
3. `depthTest: true`、`depthWrite: false`、有限の不透明度、両メッシュの個別 `geometry.dispose()` / `material.dispose()` を維持。3D終了時・画像読込失敗時のリソース解放と2Dフォールバックを守る。
4. 画像倍率・オフセットは艶の強弱と切り離す。がちもんくらぶの既存個別配置は維持し、他Communityの色補正を個別に足して基準値から分岐させない。
5. 表だけの依頼で、裏の `backMaterial`、金枠の `goldMaterial`、`pinMaterial`、刻印/焼き印、ホルダー回転、CA/Community/メダル取得履歴、DB/Storage/Auth/Campfire/APIには変更を入れない。

### 5. 次回の調整手順と合格条件

1. 要望を**対象（表/裏/金枠）×症状（色/艶/反射の移動/反射の形/位置）**に分ける。「もっと反射」は照明全体の増強を意味しない。表面の反射が弱いときは `FrontFaceReflection` を、全体の艶が足りないときだけ `FrontFaceGloss` を最初に確認する。
2. `MEDAL_DESIGN_RULES` を単一の設定正本として、原則1回につき関連するパラメータ群だけ変更する。変更前の値・変更後の値・意図・見た目のスクリーンショットを記録する。プリセット・本文・回帰テスト・読込URLのバージョンを整合させる。
3. `pages` へ直接大幅変更せず、検証ブランチ/プレビューで先に見る。構文・色忠実性・実GLBの表裏/傾き検査・Safari CORS/2Dフォールバック・公開/非公開境界のCIを通す。
4. iPhone Safariで**正面、左右に傾けた表、裏**を確認する。KOGAの黄色、KOTO KIBAの青、がちもんくらぶ、淡色・暗色で、画像の元色・文字の可読性・反射帯の移動・白い二点強反射の不在を見る。裏が従来どおりであることも確認する。
5. テスト成功は画素レベルの見た目の合格と同義ではない。実機の比較・利用者の採用判断を経てPRをマージし、GitHub Pagesデプロイ成功と反映先の表示を確認する。失敗時は最後に採用したE案へ戻せるようにする。

## 照明の基準値

| 光源 | 強度 |
| --- | ---: |
| 半球環境光 | 1.20 |
| キーライト | 1.75 |
| リムライト | 0.82 |
| 背面補助ライト | 0.40 |

値は各光源の設定値であり、加算した数値は実際の光量を表さない。

## 3D表示失敗時の原則

- 保存済み元画像を優先し、既存の代替ソースも順番に試す。
- 必要な場合のみ、認証済みCAの読み取り専用画像リレーを使用する。
- テクスチャが一つも読み込めなければ空白の3Dを表示せず2Dへ戻す。
- 既存のメダル取得、交換、Community/CA割当、画像履歴を改変しない。

## 変更時の最低限の確認

1. KOGAの黄色、がちもんくらぶの青、淡色・暗色の複数デザインで2D/3Dの色差・白いハイライトを目視確認する。
2. 金枠の金属感、裏面の刻印、ドラッグ・自動回転が残ること。
3. ADMIN見本帳と一般メダル帳の表示、未取得時のガード、iPhone Safariでの描画を確認する。
4. `node scripts/test-medal-face-hires.mjs` および `node scripts/test-medal-color-fidelity.mjs` とSafari回帰テストを通す。
5. 色調整によるDB/Storage/Auth/Campfire/API変更は行わない。Phase E凍結資産とCAマスター同期には触れない。

※ `MeshBasicMaterial` にはroughnessの意味がないため、色優先のベース面は無反射とする。E案のroughness `0.42` は**別の薄い艶レイヤーだけ**に適用する。反射帯も画像素材そのものは変更しない。白い強反射が2点強く現れないこととKOGAの黄色保持を実機で確認する。
