# CA Clover ビジュアル調整・修正履歴 共通ルール

**制定候補：2026-10-12 / 提案段階**  
適用対象：CA Clover の画面表示、3Dメダル、アイコン、地図、ボタン、画像の質感調整。  
この文書は**開発・レビューの判定ルール**。画像や本番データを書き換える指示ではない。

## 1. 目的

「直したつもりが別の不具合になる」を防ぐ。各変更を**観察 → 原因仮説 → 変更した数値・実装 → 比較 → 実機での判定 → 履歴**として残し、過去の成功・失敗から**過不足のない中間点（採用値）**を探す。

- 修正した事実と、実機で改善した事実を分ける。CI PASS は画質 PASS ではない。
- **縦横比／解像感／ホワイトバランス／黒の締まり／露出／ハイライト／反射**は別の評価軸。まとめて変更しない。
- 原本のコミュニティアイコンとユーザーの実取得データを保護する。補正は原則として**表示レイヤー**内で行う。
- 好みだけでなく、ロゴの細文字・円形・元の色・金縁・裏面刻印が読めるかで判定する。

## 2. 調整する順番（原因を混ぜない）

1. **入力品質**：元画像の画素数・アスペクト比・形式・透過・保存元URL/パスを調べる。画像が低解像度なら、露出やコントラストで「シャープになった」と誤認しない。
2. **配置・切り抜き**：中央正方形クロップ、円形マスク、文字や図柄の欠損、2D と 3D の一致。伸縮は絶対に避ける。
3. **色管理**：sRGB とテクスチャ処理、ホワイトバランス、白飛び、黒つぶれ、ブラックポイント。ロゴの固有色を変えない。
4. **3Dマテリアル**：roughness / metalness / clearcoat / tone mapping / lighting。文字の上に過度な白い反射を乗せない。
5. **最終表示**：iPhone Safari の実画面で表・斜め・裏、等倍での細文字、一覧での判読性を確認する。

同一PR内で複数軸を触る必要がある場合は、理由・変更順・各軸の確認結果を分けて記録する。

## 3. 「中間点」を見つける A/B/C 方式

- **A**：現在の採用版（戻せる基準）。
- **B**：明確に値・処理を変えた案。
- **C**：A と B の**数値上の中間値**（単一の線形パラメータなら原則 `C=(A+B)/2`）。実装方式や画像ファイルを変えた場合は単純平均できないので、A/B の効果を比較して別案を作る。
- **判定**：同一端末、ほぼ同じ画面輝度、同じ画像・角度・倍率で A/B/C を比べる。採用版を一つ選び、その理由を短く書く。
- **次の試行**：A が暗すぎ、B が明るすぎ、C が最良なら C を基準にし、残る片側との中間で絞り込む。好みが逆転したら過去の採用版まで戻れるようにする。
- 1回の比較では**1つのパラメータ群**に限定。ホワイトバランスなら色温度と tint、ブラックポイントなら黒のしきい値／カーブをそれぞれ独立に検証する。色補正の中間値は知覚的中点と一致しない可能性がある。
- A/B/C に使った数値と端末を記録できない場合は「比較未成立」。記憶だけで数値を決めない。

**説明用の架空例**：露出 A=`0.92`、試案 B=`1.02` なら C=`0.97`。これは単なる演算例であり、`1.02` や `0.97` を現在の製品で試験・採用した事実ではない。

## 4. 評価軸と記録項目

| 軸 | 何を確認するか | 原則 |
|---|---|---|
| 縦横比・クロップ | 円が楕円にならない、ロゴが欠けない | 引き伸ばさず中央を正方形に切り抜く。UI のマスクと一致 |
| 解像感 | 細文字、外周リング、線の輪郭がにじまない | 3D は保存元の原画像を先に試す。サムネイルはフォールバック |
| ホワイトバランス | 中立な白・灰色が黄／青／緑に転ばない | ロゴ原本の固有色は保存。補正量と対象レイヤーを明記 |
| ブラックポイント | 黒が灰色に浮かず、暗い細線もつぶれない | 暗部の階調と文字の判読性を両立。過度な黒締め禁止 |
| 露出・白飛び | 白文字や金縁のハイライトが消えない | 反射や照明、tone mapping との因果関係を確認 |
| コントラスト | 金色／黒背景／白文字の境界が見える | シャープネスと混同せず、輪郭の二重縁取りを避ける |
| 3D質感 | 金縁の金属感、表面の反射、裏面刻印 | 正面・斜め・裏を同じ条件で比較 |
| 性能 | iPhoneの描画速度、長時間回転、メモリ | 解像度向上で描画停止・過熱・クラッシュを起こさない |

ホワイトバランスやブラックポイントが**独立したコード上のパラメータとして存在しない場合は「未実装」**と記す。スクリーンショットの見た目から RGB・Kelvin・黒レベルを推定して「現在値」にしない。

## 5. 現在の3Dメダルにおける確認済み基準値

`docs/stamp-rally.html` の 2026-10-12 `pages` 実コードを基に記録。変更時にはここだけを見ず、必ずそのコミットのコードから再取得する。

| 設定 | 現在コードで確認した値・処理 | 備考 |
|---|---|---|
| tone mapping | `THREE.ACESFilmicToneMapping` | 描画の色調変換 |
| `toneMappingExposure` | `0.92` | **実測の最適値とは断定しない** |
| `outputColorSpace` と顔テクスチャ | `THREE.SRGBColorSpace` | カラースペースを維持 |
| 表面 `roughness` | `0.18` | マテリアル値 |
| 表面 `clearcoat` | `0.25` | マテリアル値 |
| 表面 `clearcoatRoughness` | `0.20` | マテリアル値 |
| renderer `pixelRatio` | `min(devicePixelRatio, 2)` | 端末負荷に上限あり |
| 表面テクスチャ `anisotropy` | `min(maxAnisotropy, 8)` | 斜め表示のフィルタ |
| 非正方形のクロップ | 中央正方形・出力上限1024px・高品質補間 | 原画の不足画素は復元できない |
| 3D画像の取得優先順 | archive原本 → 当該バージョンの元URL → 現行アイコン → thumb → 一覧画像 | PR #134 で修正 |
| 独立したホワイトバランス値 | **未実装／未定義** | 追加するかは別途仕様決定 |
| 独立したブラックポイント値 | **未実装／未定義** | 追加するかは別途仕様決定 |

**重要**：`roughness` などの数値は「実装に設定された値」であり、「見た目の校正を終えた実測値」ではない。画像の出典・iPhone表示・3D照明が異なれば結果も異なる。

## 8. PASS / STOP の共通基準

- **PASS（コード）**：必要な変更だけを行い、差分・CI・回帰テストが成功。
- **PASS（画像）**：同条件の実機 A/B（必要なら C）で、対象の症状が改善し、ロゴの同一性、縦横比、表裏、文字、性能に後退がない。
- **STOP**：元画像不明、比較条件不明、別の色・形状の劣化、想定外のDB/認証変更、取得・交換履歴への影響、ユーザーが見た目をまだ承認していない状態。
- 1つの修正で「正円になったが文字が滲んだ」場合は**縦横比 PASS / 解像感未PASS**のように軸別に判定する。全項目を一括「成功」にしない。
- 色校正だけのつもりで本番画像の原本を上書きしたり、全コミュニティの色を一律に補正したりしない。まず展示・開発環境で比較する。

このルールの追加自体は**仕様書変更のみ**。本番見た目・Supabase・CAマスター・メダルの保有や交換状態には変更を与えない。
